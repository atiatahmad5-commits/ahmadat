# خطة الفريق والتسليم

## نطاق النسخة المتفق عليه

رسالة أو رابط، تحليل تقني ونفسي، مؤشر واضح مع دليل، ونصيحة توقف وتحقق. الواجهة بالعربية والإنجليزية. **لا نضيف أي ميزة قبل نجاح تجربة العرض على جهازين.** الصور وQR وبيانات سمعة/عمر النطاق مؤجلة، ولا نقدمها للجنة كوظائف موجودة.

## توزيع المسؤوليات

| المسؤول | التسليم المحدد | معيار القبول |

| رشا | اختبار العربية والإنجليزية، النصوص وحالات الخطأ، العرض والتوقيت | تمر الحالات الخمس المدمجة وتبديل اللغة والمسح والتصدير؛ تنهي بروفة خلال 3–5 دقائق |
| الثلاثة | مراجعة شروط المنظمين والملكية والادعاءات | لا أرقام دقة غير مثبتة، ولا ميزة مستقبلية تعرض كمنفذة |

## مراحل قصيرة

1. **45 دقيقة:** حمودة يشغّل النسخة، أحمد يراجع السيناريوهات، رشا تختبر أمثلة الواجهة.
2. **90 دقيقة:** إصلاح العيوب المكتشفة فقط. لا توسعة ميزات. مراجعة حالة الفضول S10 وحدود النفي واللهجات.
3. **45 دقيقة:** تشغيل من مجلد نظيف على جهاز ثان، وتجربة مع الإنترنت مفصولًا.
4. **60 دقيقة:** بروفتان؛ الأولى أربع دقائق، والثانية مع أسئلة اللجنة. قياس التوقيت فعليًا.
5. **قبل التسليم:** تجميد نسخة، تأكيد commit وmaster، تنزيل PPTX من العرض، إضافة الفيديو إن طلبته الشروط، فحص الرابط من حساب آخر.

هذه مدد عمل مقترحة وليست تقديرات تنفيذ مثبتة. صفحة الحدث تعرض بدء النشاط 24 نوفمبر 2026، والتسليم 25 نوفمبر الساعة 8 صباحًا، وإغلاق تشكيل الفرق 24 نوفمبر الساعة 11 صباحًا. الصفحة لا تعرض المنطقة الزمنية صراحة في النص المسترجع؛ تأكد من المنظمين. التسجيل الفردي مطلوب لكل عضو. راجع أي رسالة أحدث قبل الاعتماد على المواعيد.

## GitHub

تم رفع المشروع إلى https://github.com/atiatahmad5-commits/ahmadat/tree/master ونجحت اختبارات النسخة المرفوعة على GitHub Actions. فرع master يحتوي المشروع كاملًا، وmain يحتوي نسخة التسليم أيضًا. لا يتضمن المشروع مفاتيح أو ملفات ضحايا. لتنزيله على جهاز حمودة:

```sh
git clone --branch master https://github.com/atiatahmad5-commits/ahmadat.git
cd ahmadat
node --test
node src/server.mjs
```

تابع التطوير على master ولا تستعمل force push. قبل التسليم تحقق من نجاح CI لأحدث commit، وأن لجنة التحكيم تستطيع القراءة، وأن README والكود والوثائق موجودة في نفس commit. بقي تنزيل ملف PowerPoint من عارض العرض وإضافته لحزمة تسليم المسابقة؛ الكود والوثائق موجودان في المستودع، لكن ملف PPTX ليس ضمنه.

## قائمة بروفة العرض

- [ ] تشغيل `node --test` ونجاح كل الاختبارات.
- [ ] تشغيل `node src/evaluate.mjs` وقراءة الحالة المفقودة لا إخفاؤها.
- [ ] تشغيل `node src/server.mjs` ثم فتح http://127.0.0.1:4173.
- [ ] المخالفة: تحقق من ظهور 55 تقني، 70 نفسي، 79 نهائي لنص المثال المدمج.
- [ ] نص عادي ونصيحة لا تشارك OTP: لا يزعم النظام أنهما آمنان قطعًا.
- [ ] طلب OTP: التحذير والنصيحة ظاهران.
- [ ] رابط @: إظهار المضيف الحقيقي بدل اسم الجهة الموجود قبل @.
- [ ] تغيير المدخل يخفي النتيجة القديمة؛ إدخال فارغ يعرض خطأ مفهومًا.
- [ ] العربية/الإنجليزية، المسح، تنزيل التقرير تعمل.
- [ ] تشغيل دون إنترنت وعلى جهاز ثان. لا ندعي اختبار ذلك قبل تنفيذه.
- [ ] العرض متاح محليًا بصيغة PPTX بعد تنزيله؛ نسخة احتياطية من الكود.
- [ ] المستودع البعيد على master ومتاح للجنة؛ تثبيت رقم النسخة.

## خطة التعافي

إذا تعطّل الجهاز: افتح نفس النسخة على جهاز حمودة الاحتياطي. إن لم يعمل المتصفح، شغّل الاختبارات والتقييم لإظهار المحرك، ثم استخدم الشرائح لتوضيح التجربة؛ لا تقدّم ذلك كعرض حي كامل. إن تعطل الإنترنت فلا يتأثر التطبيق المحلي. إن تعارض المنفذ، أغلق النسخة السابقة أو استخدم PORT مختلفًا وغيّر رابط المتصفح.

## قرار إضافة المزايا

الميزة التالية المرشحة: OCR مع تأكيد النص المستخرج، لأنها تخفف عبء النسخ. لا نضيفها قبل وجود بيانات تقييم مستقلة واستقرار العرض. السمعة وredirects تحتاج تصميم عزل واتصال خارجي؛ لا نضمها في الساعات الأخيرة. دمج LLM مفيد فقط إذا أثبت تحسنًا في اللهجة والتفسير دون تسريب بيانات أو اختلاق أدلة.
